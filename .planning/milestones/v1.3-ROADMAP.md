## Phase Details

### Phase 8: CLI Launcher
**Goal**: Users can start the full ClaudeUI application from a single terminal command
**Depends on**: Phases 1-7 (shipped)
**Requirements**: CLI-01, CLI-02, CLI-03, CLI-04, CLI-05
**Success Criteria** (what must be TRUE):
  1. User can run `cu` from any terminal and the application starts (server runs, UI loads from bundled assets)
  2. User sees clear status messages during startup: starting server, opening browser
  3. Browser auto-opens to the UI when the server is ready
  4. Pre-built UI static assets are served directly — no runtime build step
  5. If the default port is occupied, the CLI selects an available port and opens the browser to that port
**Plans**: 2 plans

Plans:
- [x] 08-01-PLAN.md — Package-aware Fastify runtime with bundled UI asset resolution, SPA fallback, and occupied-port handling
- [x] 08-02-PLAN.md — Single-command launcher flow with startup status output and browser auto-open using the actual selected URL

### Phase 9: Package and Publish
**Goal**: Users can install and run ClaudeUI globally via npm with zero additional setup
**Depends on**: Phase 8
**Requirements**: PKG-01, PKG-02, PKG-03
**Success Criteria** (what must be TRUE):
  1. User can install globally with `npm install -g @aiou/cu` and the `cu` command is available on PATH
  2. After global install, `cu` runs immediately without any build step, dev dependencies, or additional setup
  3. Package contains pre-built CLI JS and UI static assets ready to serve
**Plans**: 3 plans

Plans:
- [x] 09-01-PLAN.md — Bundle all runtime deps via tsup noExternal, configure files/publishConfig, add prepublish script for name override to @aiou/cu
- [x] 09-02-PLAN.md — Automated package verification tests confirming tarball contents, self-contained bundle, and correct configuration
- [x] 09-03-PLAN.md — Gap closure: fix ESM dynamic-require crash (switch to CJS), add build:full to prepublishOnly, add runtime smoke test

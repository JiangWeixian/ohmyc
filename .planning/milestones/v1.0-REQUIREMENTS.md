# Requirements: ClaudeUI

**Defined:** 2026-03-29
**Core Value:** Users can reliably assemble and switch between Claude-focused coding environments from reusable local components without manually editing scattered config files.

## v1 Requirements

### Store

- [x] **STORE-01**: User can import Claude-compatible agents from an existing directory into the local store
- [x] **STORE-02**: User can import Claude-compatible skills from an existing directory into the local store
- [x] **STORE-03**: User can import Claude-compatible commands from an existing directory into the local store
- [x] **STORE-04**: User can browse stored components grouped by type
- [x] **STORE-05**: User can create, edit, and delete store-managed components from the UI
- [x] **STORE-06**: User can see where a store component came from when it was imported

### Inventory

- [x] **INV-01**: User can view current AGENT_HOME components with source labels that distinguish local files, profile-linked items, and plugin-provided items
- [x] **INV-02**: User can inspect installed plugins and Claude-related configuration from the current environment
- [x] **INV-03**: User can see which profiles reference a selected store component before editing or deleting it

### Profiles

- [x] **PROF-01**: User can create a named profile from store-managed agents, skills, commands, and plugins
- [x] **PROF-02**: User can edit a profile's description, component selections, settings overlay, hooks, MCP servers, and LSP servers
- [x] **PROF-03**: User can see which components are included in a profile before activation
- [x] **PROF-04**: User can see which profile is currently active

### Activation

- [x] **ACT-01**: User can activate a profile and have Claude-compatible profile files generated in the expected directory structure
- [x] **ACT-02**: User can activate a profile and have referenced store components linked into the profile through filesystem links compatible with the current platform
- [x] **ACT-03**: User can deactivate the active profile and restore prior settings state
- [x] **ACT-04**: User can switch directly from one profile to another without manually cleaning up the previous one
- [x] **ACT-05**: User receives warnings when activation skips missing components or would apply risky changes
- [x] **ACT-06**: User is not left in a partially activated state if activation fails midway

## v2 Requirements

### Preview

- **PREV-01**: User can preview the settings and plugin changes a profile would apply before activation
- **PREV-02**: User can compare two profiles to understand the component and settings differences between them

### Adapters

- **ADPT-01**: User can import compatible assets from non-Claude coding-agent ecosystems through adapter-based conversion
- **ADPT-02**: User can see the original ecosystem/source for converted imported components

### Distribution

- **DIST-01**: User can browse remote or shared component sources in addition to the local store
- **DIST-02**: User can export a profile or component bundle for reuse on another machine

## Out of Scope

| Feature | Reason |
|---------|--------|
| A brand-new universal skill/profile specification | v1 should use Claude's existing conventions as the canonical storage model |
| Full Codex and other agent-ecosystem parity in the first release | Future ecosystems should arrive via import/adapter work after the Claude-first workflow is solid |
| Cloud-first marketplace as the primary workflow | The core product is a local-first manager for user-owned components |

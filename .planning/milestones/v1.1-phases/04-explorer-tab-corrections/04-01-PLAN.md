<objective>
Update the configs API routes to merge local config data with plugin-contributed data, tagging each entry with source and pluginId metadata.

Purpose: The current configs routes return raw local-only data with no awareness of plugin contributions. Users with plugins that provide hooks, MCP servers, or LSP servers see only their local config entries. This plan adds source-attribution merging using the same PluginResolver pattern already established in agents.ts/skills.ts/commands.ts.

Output: configs.ts routes that return arrays of tagged config entries; updated server registration; passing tests covering both local-only and plugin-merged responses.
</objective>

  <action>
    **1. Update ConfigRoutesOptions interface in configs.ts:**

    Add `pluginsDir: string` and `settingsPath: string` to the existing `ConfigRoutesOptions` interface (currently only has `baseDir: string`).

    **2. Import PluginResolver at top of configs.ts:**

    `import { PluginResolver } from '../services/pluginResolver';`

    **3. Instantiate resolver in the route handler:**

    After destructuring `{ baseDir, pluginsDir, settingsPath }` from options, create `const resolver = new PluginResolver(pluginsDir, settingsPath);`.

    **4. Update GET /api/mcp route:**

    Change the response shape from `{ mcpServers: Record<string, any> }` to `{ mcpServers: Array<{ name: string; config: any; source: 'local' | 'plugin'; pluginId?: string }> }`.

    For each entry in the local `.mcp.json` `mcpServers` object: push `{ name, config, source: 'local' }`.
    Then iterate `resolver.getEnabledPluginPaths()` -- for each plugin, read `.mcp.json` from its installPath. For each entry in the plugin's `mcpServers`, push `{ name, config, source: 'plugin', pluginId: id }`.

    If a name collision occurs between local and plugin, include both entries. The plugin entry keeps its original name (the SourceBadge on the frontend distinguishes them visually).

    **5. Update GET /api/hooks route:**

    Hooks have a nested event-keyed structure: `{ PreToolUse: [{ matcher, hooks: [{ type, command }] }] }`.

    For the merged response, change to an array-of-tagged-entries approach. Each entry is:
    `{ event: string; name: string; data: { matcher?: string; type: string; command: string }; source: 'local' | 'plugin'; pluginId?: string }`.

    Process local hooks: for each event name in `settings.hooks`, iterate each hook group, then iterate each hook within the group's `hooks` array. Tag each individual hook with `source: 'local'`, `event: eventName`. For the `name` field, use a composite: `"{event} [{index}]"` (e.g., "PreToolUse [0]").

    Process plugin hooks: for each enabled plugin, read `hooks/hooks.json` from its installPath. Apply the same flattening logic, tagging each hook with `source: 'plugin'` and `pluginId`.

    Return `{ hooks: entries }`.

    **6. Update GET /api/lsp route:**

    Same pattern as /api/mcp but reading `.lsp.json`. The local `.lsp.json` may be a flat object (not wrapped in a top-level key). Read the full file and treat each top-level key as a server entry.

    Return `{ lspServers: entries }` where each entry has `{ name, config, source, pluginId? }`.

    **7. Update server registration in index.ts:**

    Change line 68 from:
    `await fastify.register(configsRoutes, { baseDir });`
    to:
    `await fastify.register(configsRoutes, { baseDir, pluginsDir, settingsPath });`

    The variables `pluginsDir` and `settingsPath` are already defined on lines 61-62.

    **8. Update tests in configs.test.ts:**

    The existing test setup only passes `{ baseDir: tmpDir }`. Update to also pass `pluginsDir` and `settingsPath`:
    - Create a `plugins` subdirectory in tmpDir
    - Create a `settings.json` in tmpDir
    - Pass `{ baseDir: tmpDir, pluginsDir: path.join(tmpDir, 'plugins'), settingsPath: path.join(tmpDir, 'settings.json') }`

    Update existing tests to match new array response shape:
    - The "returns empty" tests should expect `{ mcpServers: [] }` (empty array, not empty object)
    - The "returns mcpServers" test should check that `res.json().mcpServers` is an array, entries have `source: 'local'`, and the config data is preserved

    Add new tests for plugin merging:
    - Create a plugin install directory with `.mcp.json`, enable it in `settings.json`, and verify the plugin entry appears with `source: 'plugin'` and correct `pluginId`
    - Create a disabled plugin and verify its entries do NOT appear
    - Same pattern for hooks and LSP tests

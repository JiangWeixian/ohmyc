2. Add `splitting: false` to the tsup config to prevent code splitting. The current build produces chunk-*.js and src-*.js files alongside index.js. Setting `splitting: false` forces everything into a single index.js file. This is critical because the `files` field will specify `dist/index.js` specifically, and missing chunk files would cause runtime failures.

3. Keep the existing `onSuccess` hook that copies UI assets -- do not modify it.

4. Add `clean: true` to ensure dist is cleared before each build (avoids stale chunk files from previous builds).

The final config should look like:
```typescript
import { defineConfig } from 'tsup';
import { cpSync, existsSync } from 'fs';
import path from 'path';
import { fileURLToPath } from 'url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));

export default defineConfig({
  entry: ['src/index.ts'],
  format: ['esm'],
  splitting: false,
  clean: true,
  noExternal: [
    '@claudeui/shared',
    '@fastify/static',
    'cac',
    'fastify',
    'get-port',
    'gray-matter',
    'open',
    'proper-lockfile',
    'zod-to-json-schema',
  ],
  onSuccess: async () => {
    const uiDist = path.resolve(__dirname, '../ui/dist');
    const cliUiDist = path.resolve(__dirname, 'dist/ui');
    if (existsSync(uiDist)) {
      cpSync(uiDist, cliUiDist, { recursive: true });
      console.log(`Copied UI assets from ${uiDist} to ${cliUiDist}`);
    } else {
      console.warn(`Warning: UI dist not found at ${uiDist}. Run 'pnpm --filter @claudeui/ui build' first.`);
    }
  },
});
```

**3. Create `packages/cli/scripts/prepublish.mjs`:**

This script handles the name override and dependency clearing that npm's publishConfig cannot do (per D-01, D-03, D-09). The script must:

a) Read `package.json`
b) Check that `dist/index.js` exists (if not, error with message: "dist/index.js not found. Run pnpm build:full first.")
c) Check that `dist/ui/index.html` exists (if not, error with message: "UI assets not found. Run pnpm build:full first.")
d) Temporarily modify the in-memory package.json: set `name` to `@aiou/cu`, set `dependencies` to `{}`
e) Write the modified package.json to disk
f) On exit (success or failure), restore the original package.json using a finally block or process event handlers

The script pattern:
```javascript
import { readFileSync, writeFileSync, existsSync } from 'fs';
import { join, dirname } from 'path';
import { fileURLToPath } from 'url';

const __dirname = dirname(fileURLToPath(import.meta.url));
const pkgPath = join(__dirname, '..', 'package.json');

// Pre-flight checks
if (!existsSync(join(__dirname, '..', 'dist', 'index.js'))) {
  console.error('dist/index.js not found. Run pnpm build:full first.');
  process.exit(1);
}
if (!existsSync(join(__dirname, '..', 'dist', 'ui', 'index.html'))) {
  console.error('UI assets not found. Run pnpm build:full first.');
  process.exit(1);
}

// Read original and save backup
const original = readFileSync(pkgPath, 'utf-8');
const pkg = JSON.parse(original);

// Restore original on any exit
const restore = () => writeFileSync(pkgPath, original);
process.on('exit', restore);
process.on('SIGINT', () => { restore(); process.exit(130); });
process.on('SIGTERM', () => { restore(); process.exit(143); });

// Modify for publishing
pkg.name = '@aiou/cu';
pkg.dependencies = {};

// Write modified version (npm reads this during publish)
writeFileSync(pkgPath, JSON.stringify(pkg, null, 2) + '\n');
console.log('Package configured for publication as @aiou/cu');
console.log('Original package.json will be restored after publish completes.');
```

CRITICAL: The `process.on('exit')` handler ensures the original package.json is restored even if npm publish fails. The script does NOT run the build itself -- that should be done before `npm publish` is called. The `prepublishOnly` lifecycle hook runs automatically before `npm publish`, and the restore happens on process exit.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine -> npm registry | Publishing credentials (npm token) transmitted over HTTPS |
| Published tarball -> end user | Package contents downloaded by users after global install |
| prepublish script -> package.json | Script modifies package.json in-place during publish lifecycle |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Information Disclosure | Published tarball | mitigate | `files` allowlist in package.json limits tarball to `dist/` and `README.md` only. No source code, tests, .env, or config files can be published. |
| T-09-02 | Tampering | prepublish.mjs | accept | Script runs on developer machine during publish. Low risk -- developer controls the script content. Restore-on-exit prevents accidental persistent modification. |
| T-09-03 | Tampering | Bundle output | mitigate | `splitting: false` + explicit `noExternal` list ensures all code is in a single deterministic file. No external runtime dependency resolution = no supply chain tampering via dependency confusion. |
| T-09-04 | Spoofing | @aiou npm scope | accept | npm org controls who can publish under @aiou. Standard npm authentication. Not a code-level mitigation. |
| T-09-05 | Information Disclosure | prepublish script | accept | Script temporarily writes @aiou/cu to package.json but restores immediately. No secrets involved. The temporary state exists only during npm publish lifecycle. |
</threat_model>

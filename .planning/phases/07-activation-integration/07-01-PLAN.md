<objective>
Extend ProfileService backend with model config environment variable injection during activation and modelConfigChanges computation during preflight.

Purpose: When a profile with a model config is activated, write ANTHROPIC_API_KEY, ANTHROPIC_BASE_URL, and (conditionally) ANTHROPIC_MODEL into the settings.json env field. Preflight computes SET/CHANGE/REMOVE preview data so the frontend can display what will change before the user confirms.

Output: Extended ProfileService with env var injection and preflight modelConfigChanges, fully tested.
</objective>

    **Part A: Extend activate() Step 10**

    In profileService.ts, inside the `activate()` method, AFTER the existing settings merge block (`if (profile.settings) { merged = this.deepMerge(...) }`) and BEFORE the enabledPlugins block, insert:

    ```typescript
    // Inject model config env vars
    if (profile.modelConfig) {
      const mc = await this.modelConfigService.get(profile.modelConfig);
      if (mc) {
        const envVars: Record<string, string> = {};
        envVars['ANTHROPIC_API_KEY'] = mc.apiKey;
        envVars['ANTHROPIC_BASE_URL'] = mc.baseUrl;
        if (mc.modelName) {
          envVars['ANTHROPIC_MODEL'] = mc.modelName;
        }
        merged.env = { ...(merged.env || {}), ...envVars };
      }
      // If model config not found (deleted between preflight and activation), skip silently
    }
    ```

    Key design decisions baked in:
    - Spread `merged.env || {}` first, then spread `envVars` on top -- model config values ALWAYS win over profile.settings.env keys (Pitfall 2 from RESEARCH.md)
    - Uses real values from model config (NOT masked preflight data) -- masking is for display only (Pitfall 4)
    - If model config is deleted, `mc` is null, so the if-block is skipped -- activation proceeds without env vars

# Phase 15.1: Unify Component Library - Context

**Gathered:** 2026-04-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace all @base-ui/react-based shadcn components with @radix-ui/react-based uitripled equivalents. Reduce raw @radix-ui usage by ensuring all components come through the uitripled/shadcn abstraction. The app must remain visually identical — this is a dependency unification, not a visual redesign.

13 components currently use @base-ui/react and need migration:
- avatar, badge, button, checkbox, dialog, dropdown-menu, input, scroll-area, select, separator, slider, switch, tabs, tooltip

2 native wrappers already use raw @radix-ui but live in the uitripled directory (native-dialog, native-tooltip).

After migration, remove @base-ui/react from dependencies.

</domain>

<decisions>
## Implementation Decisions

### Migration Approach
- **D-01:** Use shadcn CLI installation pattern (per uitripled documentation) to install components. Components are sourced from the uitripled vendor directory or its registry, not manually copied.
- **D-02:** All 13 @base-ui/react components are replaced with their @radix-ui/react equivalents from uitripled. Each component is installed individually via the shadcn pattern.
- **D-03:** Maintain existing component APIs where possible. If uitripled's API differs from current @base-ui version, add thin compatibility wrappers to avoid changing consumer code.

### scroll-area
- **D-04:** Use uitripled's scroll-area implementation (pure div with webkit scrollbar styling) instead of @base-ui/react's scroll-area.
- **D-05:** Preserve ClaudeUI's custom scrollbar appearance by adding project-specific CSS overrides for scrollbar thumb/track colors using existing CSS custom properties (`--border-*`, `--surface-*`).

### native-dialog & native-tooltip
- **D-06:** These are already uitripled components — they live in `packages/ui/src/components/uitripled/` and are the project's native animated wrappers. No change needed.
- **D-07:** They serve as the canonical animated dialog/tooltip implementation. Any future dialog/tooltip work should use these, not raw @radix-ui imports.

### Dependency Management
- **D-08:** After all components are migrated, remove `@base-ui/react` from `packages/ui/package.json` dependencies.
- **D-09:** Verify no other files import from `@base-ui/react` before removal. The only expected consumers are the 13 UI components being migrated.

### Verification
- **D-10:** Run the existing test suite after migration to catch any API mismatches.
- **D-11:** Do a manual smoke test of key flows (profile switching, component editing, settings) to ensure no visual or behavioral regressions.

### Agent's Discretion
- Exact shadcn CLI command or installation mechanism (npx shadcn@latest add vs manual copy from vendor)
- Whether to batch-install all components at once or incrementally
- Scrollbar CSS override implementation details
- How to handle any API incompatibilities between @base-ui and @radix-ui versions

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **@radix-ui packages** already installed in package.json (all versions match uitripled requirements)
- **cn() utility** at `@/lib/utils` — used by all components, remains unchanged
- **uitripled barrel export** at `@/components/uitripled/index.ts` — already re-exports native wrappers

### Established Patterns
- **shadcn component structure**: Each component is a self-contained file with imports from `@radix-ui/react-*` or pure React
- **CSS custom properties**: All colors via `var(--surface-*)`, `var(--border-*)`, `var(--text-*)`, `var(--accent-*)`
- **cn() composition**: Every component uses `cn()` for conditional class merging
- **"use client" directives**: Present in interactive components (Radix-based ones)

### Integration Points
- All migrated components are imported by feature components (EntityCard, ProfileCard, Settings, etc.)
- No changes to consumer component APIs — migration is transparent to callers
- ScrollArea is used in Sidebar and Explorer for scrollable content areas

</code_context>

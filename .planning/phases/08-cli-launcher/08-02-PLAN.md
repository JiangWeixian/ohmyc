<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Terminal input → CLI parser | User-supplied args and env can influence launch behavior |
| CLI launcher → browser opener | External app launch occurs after building a local URL |
| CLI launcher → package metadata | Bin mapping determines which built file executes when the user runs `cu` |
| CLI launcher → stdout/stderr | User relies on output for startup state and troubleshooting |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-05 | T | `packages/cli/src/index.ts` URL construction | mitigate | Build the browser URL from the trusted `startServer()` result and localhost address pattern rather than interpolating arbitrary user strings into a shell command. |
| T-08-06 | R | launcher status output | mitigate | Emit deterministic startup messages before and after server listen so failures are attributable and Phase 8 UX remains debuggable. |
| T-08-07 | D | browser opener integration | mitigate | Only invoke the browser opener after successful server startup and catch launcher errors to avoid hanging or repeated open attempts. |
| T-08-08 | E | CLI command exposure | accept | MVP launcher remains a local developer utility without auth; no privilege boundary change is introduced by opening a local browser tab. |
| T-08-09 | S | `packages/cli/package.json` bin mapping | mitigate | Verify `cu` maps to the intended built entrypoint so the shipped command cannot silently drift to a different executable than the tested launcher path. |
</threat_model>

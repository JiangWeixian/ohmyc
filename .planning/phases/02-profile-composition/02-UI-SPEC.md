## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, chip separators |
| sm | 8px | Compact control spacing, label-to-helper gaps |
| md | 16px | Default control padding, card internals, form row spacing |
| lg | 24px | Section padding, left/right column interior spacing |
| xl | 32px | Gaps between major cards in the detail layout |
| 2xl | 48px | Break between editor sections on long single-page forms |
| 3xl | 64px | Page-level top spacing and empty-state breathing room |

Exceptions: 44px minimum hit area for icon-only controls or compact activation actions; 1px border width throughout

## Phase 02 Visual And Interaction Contracts

### Profile detail

- The primary focal point of the detail view is the profile name plus `Active` badge in the summary rail.
- Use a two-column layout at desktop widths.
- Left column is the summary rail: profile name, active badge, description, primary actions, and secondary technical metadata.
- Right column contains exactly two stacked sections: `Components` and `Runtime config`.
- Replace count-first cards as the primary comprehension device. Counts may remain secondary metadata inside each section header.
- Show included component names as scanable lists grouped into `Agents`, `Skills`, `Commands`, and `Plugins`.
- Show runtime configuration as key-name summaries grouped into `Hooks`, `MCP`, `LSP`, and `Settings`.
- Never render raw JSON as the default detail presentation. Raw payloads are for editing only.
- If generated profile path is shown, render it as muted secondary metadata under the summary rail, never as the primary active-state signal.

### Active state

- Active state must be expressed by profile name consistently in sidebar, detail header, and activation feedback.
- Use a text badge labeled `Active` next to the profile name. Do not rely on a star-only indicator.
- Use the same active badge treatment in list and detail so the user does not have to reinterpret status between surfaces.
- Activation feedback should name the profile directly: `Activated {profileName}`.
- Avoid filesystem-path language in primary copy. Path details, if shown, belong in subdued technical metadata.

### Profile editor

- Keep a single-page editor with exactly three sections in this order: `Basics`, `Selections`, `Runtime config`.
- `Basics` contains name and description only.
- `Selections` contains four grouped pickers: `Agents`, `Skills`, `Commands`, `Plugins`.
- `Runtime config` contains four grouped JSON editors with helper text that explains each block at a key-name level.
- Each section should start with a section heading and one short sentence of helper copy.
- Keep save and cancel actions pinned to the header of the editor card.
- Show validation and parse failures inline near the failing section, not only as a distant global banner.

### Runtime config readability

- Summaries must list top-level keys only.
- Empty runtime groups should render an explicit empty state such as `No hooks configured`.
- For non-empty groups, use compact chips or stacked key rows with monospace only for the key name itself.
- Keep each runtime group visually equivalent so `Hooks`, `MCP`, `LSP`, and `Settings` read as one family.
- Do not introduce profile-vs-profile compare UI, activation diffs, or merged-output previews in this phase.

### Component inclusion readability

- Component groups must preserve the Phase 1 taxonomy: `Agents`, `Skills`, `Commands`, `Plugins`.
- Inside each group, prioritize readable names over dense metadata.
- Empty groups should say `No {group} selected`.
- If a group is long, allow wrapping or vertical stacking before truncating names aggressively.
- Use secondary muted text for descriptions when available, but the name remains the primary line.

### Motion and states

- Preserve the repo's existing restrained motion style: opacity/transform only, 150-200ms max.
- Avoid decorative motion on load beyond minor entrance easing already used in the app.
- Hover should slightly raise contrast or border visibility; no layout shift.
- Focus state is always a 2px outline/ring in accent blue with 2px offset.
- Disabled controls use 50% opacity and `not-allowed` cursor.

### Accessibility and responsiveness

- Maintain 4.5:1 contrast for all text against dark surfaces.
- Icon-only controls require an `aria-label`.
- Detail layout collapses to a single column below the desktop breakpoint, with summary first and scan sections following.
- Sidebar/profile selection rows and primary action buttons must remain usable on narrow widths without clipping the profile name.

### Source Notes

- Locked from `02-CONTEXT.md`: two-column detail layout, single-page editor sections, active-name semantics, and pre-activation readability scope.
- Inherited from existing repo UI: Inter font, dark token palette, 17px body text, 2px focus ring, 6-8px radii, and manual React + Tailwind component system from `packages/ui/src/globals.css`.
- Defaulted for this phase: 4/8/16/24/32/48/64 spacing contract, `Active` badge wording, empty/error/destructive copy, and 44px minimum compact hit area.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CWD → Server | Project `.claude/` directory contents are read from filesystem. Any files placed there by any process are served via API. |
| API → UI | Merged results include project-scoped items that are view-only. UI must enforce no-edit constraint. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Spoofing | agents/skills/commands routes | accept | Project items are distinctly tagged with source 'project' and scope 'project', preventing confusion with global items. UI renders a green "project" badge. |
| T-11-02 | Tampering | configs route (project settings.json) | accept | Project directory files are read-only by design (D-06). No write endpoints for project items. This is expected behavior — project config is managed outside ClaudeUI. |
| T-11-03 | Information Disclosure | project directory file reads | mitigate | Ensure route handlers only read from ConfigLocator-resolved project subdirectories (projectAgentsDir, projectSkillsDir, etc.), never from arbitrary paths. Verify null checks prevent reading unintended directories. |
| T-11-04 | Elevation of Privilege | scope field assignment | mitigate | Scope is computed server-side from directory source, never accepted from client input. Items from projectAgentsDir always get scope 'project'; items from agentsDir always get scope 'global'. No client-controlled field. |
</threat_model>

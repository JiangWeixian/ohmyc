## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, dense metadata separation |
| sm | 8px | Compact control gaps, stacked label spacing |
| md | 16px | Default control spacing, row padding, card internals |
| lg | 24px | Section padding, dialog body padding |
| xl | 32px | Major layout gaps between list/detail regions |
| 2xl | 48px | Empty-state vertical spacing, large panel breathing room |
| 3xl | 64px | Page-level vertical rhythm for full-screen sections |

Exceptions: 44px minimum hit target for icon-only actions; existing 6px and 8px radii remain allowed because they are already established in `packages/ui/src/globals.css`

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Rules:
- Use exactly these four sizes for new Phase 1 UI.
- Use exactly these two weights for new Phase 1 UI: 400 and 600.
- Reserve `Display` for page titles or import dialog titles only.
- Use tabular numerals for profile reference counts, timestamps, and inventory counts.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#080A0A` | App background, full-height shell, empty canvas areas |
| Secondary (30%) | `#0F1112` | Cards, list rows, dialogs, raised store/inventory surfaces |
| Accent (10%) | `#5E6AD2` | Primary CTA, active filters, focused search field, selected list item border, source-detail links |
| Destructive | `#E0675C` | Delete, overwrite-destructive confirmation, irreversible warnings only |

Accent reserved for: primary import action, active tab/filter chips, keyboard focus ring, selected entity/list state, provenance affordances such as “view source details”; never use accent for every interactive element

Supporting semantic colors from the current repo remain valid:
- `#8F7BF5` for plugin-provided source badges only
- `#D8AB45` for warnings, conflict summaries, and overwrite-risk messaging only
- `#4DA36F` for non-destructive success confirmation only

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Import Components |
| Empty state heading | No components in this store yet |
| Empty state body | Import agents, skills, or commands from an existing Claude-compatible directory to start building a canonical local store. |
| Error state | Couldn’t complete this action. Review the conflicting items or filesystem details, then try again. |
| Destructive confirmation | Delete component: “Delete this store component?”; Force overwrite import: “Overwrite existing components?”; Force delete referenced component: “This component is still referenced by profiles. Delete anyway?” |

Additional copy rules:
- Use “store” for canonical managed assets and “current environment” for AGENT_HOME inventory.
- Use “source” labels exactly as `local`, `profile`, and `plugin` in inventory views (source: `01-CONTEXT.md`).
- Provenance detail copy must stay lightweight: show import path and import time only.
- Inventory views are read-only in Phase 1. Do not label inventory actions with edit verbs.

---

## Interaction Contract

- The primary focal point of the main store screen is the store list itself. If the store is empty, the primary focal point becomes the empty-state heading and `Import Components` CTA.
- Keep the store browsing view minimal and scan-first. Primary row content is type, name, description, and profile reference count.
- Support name search and type filtering in the store list header area. Search should filter in place without route changes.
- Keep provenance discoverable but secondary. Surface provenance in row-adjacent detail, tooltip, hover card, or expandable metadata, not as a dominant column.
- Inventory surfaces remain inspection-only. Local, profile-linked, and plugin-provided items can be opened for detail but not edited inline.
- Import conflict handling must show all detected name collisions before execution and provide explicit confirmation plus a one-click `Overwrite All` path.
- Destructive and irreversible actions use modal confirmation, dim the background, and keep the destructive button visually distinct with the destructive color.
- Errors must appear at the action point: import dialog, delete dialog, or inline form region. Do not rely on detached global-only failure messaging.
- Use skeletons or inline loaders for lists and detail panes; preserve layout during loading.
- Motion stays subtle and short. Limit interaction feedback to opacity and transform transitions at 150-200ms and respect reduced-motion settings.

---

## Component Inventory

- Store list rows: rounded raised panels using the existing `panel`/raised-surface language
- Search input: single-line filter field above the list
- Type filter: segmented control or select aligned with the current header pattern
- Source badge: compact uppercase chip for `profile` and `plugin`; add a neutral variant for `local` when needed
- Provenance detail: hover card, tooltip, or inline metadata block with import path and import time
- Import conflict dialog: summary, collision list, cancel, confirm overwrite, and `Overwrite All`
- Delete confirmation dialog: preserve current modal pattern, but apply the Phase 1 copy contract
- Empty state panel: centered heading, one-sentence explanation, one primary CTA

## API Response Contract (for Phase 6 consumption)

This section defines the exact response shapes the backend must produce. Phase 6 will render these in UI components.

### Model config object shape

```typescript
{
  name: string;        // unique identifier, immutable
  apiKey: string;      // stored plain text, masked in Phase 6 UI
  baseUrl: string;     // any string accepted (no URL validation)
  modelName: string;   // any string accepted, defaults to ""
  provider: string;    // any string accepted, defaults to ""
}
```

When returned from the API with provenance, the shape includes an optional `provenance` field and an `id` field set equal to `name` for compatibility with the existing `attachProvenance` helper.

### Endpoints

| Method | Path | Success Status | Success Body | Error Statuses |
|--------|------|----------------|--------------|----------------|
| GET | `/api/store/model-configs` | 200 | `{ modelConfigs: ModelConfigWithProvenance[] }` | N/A |
| GET | `/api/store/model-configs/:name` | 200 | `ModelConfigWithProvenance` | 404 `{ error: string }` |
| POST | `/api/store/model-configs` | 201 | `ModelConfig` | 400 (validation), 409 (duplicate name) |
| PUT | `/api/store/model-configs/:name` | 200 | `ModelConfig` | 400 (validation), 404 (not found) |
| DELETE | `/api/store/model-configs/:name` | 200 | `{ success: true }` | 404 (not found), 409 (referenced by profiles) |

### 409 Conflict response (delete blocked)

```json
{
  "error": "Cannot delete model config \"claude-pro\" because it is referenced by the following profiles.",
  "profiles": ["work-profile", "personal-profile"]
}
```

Phase 6 will render the `profiles` array as clickable profile names or reference badges, consistent with the existing `referencedByMap` pattern from `StoreComponentList`.

### 400 Bad Request response (validation)

```json
{
  "error": "Model config name \"invalid name!\" is invalid: must match [a-zA-Z0-9_-]"
}
```

Or for duplicate:

```json
{
  "error": "Model config \"existing-name\" already exists"
}
```

### ProfileSchema extension

The `ProfileSchema` gains an optional `modelConfig` field:

```typescript
modelConfig: z.string().optional()  // single model config name reference
```

This is a scalar string (not an array), unlike agents/skills/commands. Phase 6 will render this as a single-select picker in the profile editor.

## Phase 06 Preparation Notes

The following UI elements are deferred to Phase 6 but documented here so the backend produces the right data shapes:

1. **Store tab for model configs:** The Explorer sidebar `SECTIONS` array will need a new `{ id: 'model-configs', label: 'Model Configs', icon: Cpu }` entry. The backend list endpoint provides the data.

2. **API key masking:** The backend stores API keys as plain text. Phase 6 must mask to last 4 characters in both list and edit views. The masking is purely a frontend transformation: `key.length > 4 ? '****' + key.slice(-4) : '****'`.

3. **Profile model config picker:** The profile editor needs a single-select dropdown picking from `GET /api/store/model-configs`. The `ProfileSchema.modelConfig` field is the stored reference.

4. **Delete reference protection:** Phase 6 renders the 409 `profiles` array as reference badges using the same chip pattern from `StoreComponentList` (blue pill for 1-2 refs, summary text for 3+).

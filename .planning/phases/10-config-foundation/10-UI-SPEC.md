## Component Changes

### SourceBadge: Add `project` Variant

**What:** Add a fourth source variant to the existing SourceBadge component.

**Type change:**
```typescript
// Before
type InventorySource = 'local' | 'profile' | 'plugin';

// After
type InventorySource = 'local' | 'profile' | 'plugin' | 'project';
```

**Render logic (insert before `return null`):**
```typescript
if (source === 'project') {
  return (
    <span className="rounded-[var(--radius-sm)] bg-[#22c55e]/10 px-2 py-0.5 text-[10px] font-semibold uppercase text-[#22c55e]">
      project
    </span>
  );
}
```

**Pattern adherence:**
- Uses `rounded-[var(--radius-sm)]` -- matches existing variants
- Uses `px-2 py-0.5` -- matches existing variants
- Uses `text-[10px] font-semibold uppercase` -- matches existing variants
- Uses `{color}/10` bg with `{color}` text -- matches profile (blue) and plugin (purple) patterns
- No pluginId sub-label -- matches local and profile patterns (only plugin has a sub-label)

**Color note:** Uses hardcoded `#22c55e` rather than a CSS custom property because:
1. D-06 locks this specific hex value
2. It differs from the existing `--accent-green: #4da36f` token
3. Adding a new CSS custom property for a single badge variant is premature; if more project-themed elements appear in Phase 11, a `--accent-project` token can be extracted then

### Shared Schema Updates (Non-Visual but Required for UI Type Safety)

The `InventorySource` type in SourceBadge.tsx is local. The shared schemas (`agentSchema.ts`, `skillSchema.ts`, `commandSchema.ts`) each define a `z.enum(['local', 'profile', 'plugin'])` for the source field. All three must add `'project'` so that API responses carrying `source: 'project'` type-check correctly. This enables Phase 11 to pass project-sourced items through the existing data pipeline.

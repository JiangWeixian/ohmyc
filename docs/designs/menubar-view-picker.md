## Problem Statement

The Popover currently owns a temporary Area / Heatmap switch, although view preference is not a high-frequency task. A plain `Chart type` setting would remove that chrome but make the user choose an abstract label without seeing the resulting information density. The Settings page should let users compare complete Popover layouts visually, then make the Popover read-only and persistent.

## What Makes This Cool

The picker borrows the useful part of Apple's widget gallery: a large, tilted preview inside a carousel, side previews, pagination, and an explicit Apply action. Real OhMyC charts and Quota data make the preview meaningful. Pointer-follow tilt, local monochrome glow, and a subtle `1.02` hover scale make the preview feel tangible without adding animation to the actual monitoring surface.

Approved interactive reference: visual-companion `menubar-widget-gallery-v6.html`, approved by the user on 2026-11-08.

## Premises

- View selection belongs in Settings, not in the transient Popover.
- The preview must use the same components and data as the real Popover; a static replica would drift.
- Layout visibility and Quota polling are independent. Choosing `Quota Focus` or an Activity layout never enables, disables, or contacts a provider.
- Browsing layouts is not applying them. Only the bottom Apply action writes settings.

## Constraints

- Preserve the existing theme tokens, dark monitor register, WCAG 2.1 AA, keyboard parity, and `prefers-reduced-motion` behavior.
- Desktop/Tauri only. Plain web keeps the existing Appearance-only Settings fallback.
- Reuse the existing settings resolve/write/broadcast path and its env > file > default contract.
- Keep the Popover compact and height-bounded. The preview must not run Popover autosize or window actions.
- Update `DESIGN.md` before product code, including a Decisions Log entry.
- Do not commit the temporary `.superpowers/` demo as product code.

## Approaches Considered

### Approach A: Static preview

Build Settings-only miniature charts, persist the selected layout, and leave the real Popover components separate. This has the smallest initial diff but duplicates rendering, uses sample data, and will drift from the actual product. Rejected for that reason.

### Approach B: Shared real components — selected

Extract presentational Popover content so Settings and `/menubar` render the same Activity and Quota components with real data. Add a Settings-only gallery shell for carousel and pointer interaction. This costs more refactoring but preserves the central promise that the preview is the real result.

## Recommended Approach

### Layout presets

Use the existing view vocabulary in storage and add one new value:

| Stored value | Display name | Composition |
| --- | --- | --- |
| `area` (default) | Trend & Quota | Area chart, Tokens/Sessions/Peak KPI, existing top-3 Quota section |
| `heatmap` | Bricks & Quota | 16-week heatmap, the same KPI and Quota section |
| `quota` | Quota Focus | Quota pressure hero plus the four most-constrained displayable providers and `+N more` |

Activity presets retain the existing 16-week calculations, tooltips, units, stale-data behavior, and footer. `Quota Focus` reuses the same ranking, account-window-only rule, pressure computation, and stale-carrying behavior. It does not introduce a new provider allowlist.

`Quota Focus` never collapses to a blank Popover. Initial loading shows a labeled `Loading quota…` state without a skeleton. No displayable data shows `No quota data yet`; errors without stale data show `Quota unavailable`. Render average and peak independently when only one is available, with em dashes for unknown values rather than fabricated zeros. The pressure/header/footer stay visible while an over-height provider list becomes keyboard-accessible and scrollable within the available Popover space; the preview uses the same bounded list, and no provider rows are clipped or made unreachable.

### Settings page

Add a `Menu bar` section between Quota and Appearance. It contains:

- A horizontal, scroll-snap carousel with one large centered preview and dimmed side previews.
- Arrow buttons, pagination dots, touch/trackpad scrolling, and Left/Right keyboard navigation.
- Preset name and one-line description below the preview.
- A bottom `Use …` button. Browsing updates only local preview state; Apply writes the setting. The currently applied preset shows its selected state.
- The existing menu bar icon visibility row and its hide confirmation, moved here from Appearance to keep all Popover preferences together. This is an assistant-proposed placement confirmed by the approved demo structure.

Preview chart tooltips and `Open OhMyC` are non-interactive and cannot activate windows or hide the Popover. The preview exposes an accessible text summary. The sole interaction exception is an over-height Quota Focus provider region: it has an accessible name such as `Quota providers, scrollable`, participates in normal Tab order, and supports arrow/Page/Home/End scrolling so every row remains reachable. Loading, empty, stale, and error states render through the same components as the real surface rather than fabricated sample values.

When `menubarView` is env-overridden, the gallery remains readable but Apply and layout-changing controls are disabled with the existing `EnvNote` treatment. While an Apply write is in flight, prevent duplicate writes and keep the previous applied state until the resolved response/event arrives. A rejected or failed write performs no optimistic applied-state update, re-enables the controls, retains the user's browsed preset and the last resolved applied state, and exposes an inline `Couldn't save menu bar view. Try again.` error with the same Apply button as the retry path.

### Actual Popover

Remove the header `ViewSwitch`, its local `useState<MenubarView>`, and its now-obsolete component/Story references. `MenubarPage` reads `menubarView` from `useAppSettings`, defaulting to `area` only while resolved settings are unavailable. It renders the selected preset without any temporary override.

The existing `settings:changed` subscription and focus/visibility invalidation keep the main window and Popover synchronized. No new polling or event channel is needed.

### Shared component structure

- Extract Activity/KPI/footer presentation from `menubar-page.tsx` into a reusable component parameterized by view and data, leaving setup gating and Popover autosize in `/menubar`.
- Keep `AreaTrendChart`, `RecentHeatmap`, and `MenubarQuotaSection` as the rendering sources of truth.
- Extend the Quota presentation with a focus composition rather than duplicating ranking, formatting, or pressure calculations.
- Add a Settings-only `MenuBarViewGallery` / preview frame that owns carousel state, pointer interaction, and accessible selection controls. It does not own Timeline or Quota data mutations.

### Motion and pointer interaction

The preview frame preserves the approved static perspective. Fine-pointer hover adds small pointer-follow X/Y tilt, local monochrome surface/border glow, and `scale(1.02)`. The carousel and gallery controls remain still.

Use the approved spring-follow version, not the rejected direct 1:1 experiment. Spring response is `0.3`, critically damped with no intentional overshoot. Pointer listeners live on the stable outer slide with a `12px` hover allowance so perspective-transformed corners, especially the upper-right, do not lose events. Pointer leave restores the base angle and scale and fades the glow.

Only `transform` and opacity-driven effects animate. Touch/coarse pointers do not run hover tracking. Reduced motion disables pointer tracking, scale interpolation, and glow; instant layout/carousel changes remain available. No ambient or looping animation is added.

### Settings schema and resolution

Keep schema version 1 and add an optional field. Old files work in the new build, and older builds can launch with the default layout. Downgrade writes are explicitly not preference-preserving: an older build that rewrites `settings.json` may discard the newer `view` field, so users who downgrade and then change settings must select their view again after upgrading.

```json
{
  "menubar": {
    "iconVisible": true,
    "view": "heatmap"
  }
}
```

Add `menubarView: ResolvedSetting<"area" | "heatmap" | "quota">` to the frontend contract and `SettingsPatch.menubar.view`. Store the raw file patch value as `Option<String>` rather than a Serde enum, and validate it only in the field-local resolve/patch paths so an unknown view cannot invalidate unrelated settings. Add `OHMYC_MENUBAR_VIEW` with the same env > file > default precedence. The default is `area` to preserve current behavior. An invalid environment value is ignored so a valid file value still wins; an invalid or missing file value falls back to `area`. Invalid patches are rejected before writing. Sparse merge preserves `iconVisible` when only `view` changes and vice versa. A test must place an invalid view beside valid Quota, icon, and theme values, verify those values survive resolution, then perform an unrelated sparse write and verify they remain intact.

## Non-goals

- Arbitrary widget composition, resizing, reordering, or user-created presets.
- Per-provider Popover visibility rules or a Chart-only preset.
- Changes to Quota polling, credentials, metrics, or Timeline statistics.
- Pointer tilt, glow, or carousel chrome in the actual Popover.
- A general light mode or a new component library.

## Success Criteria

- The Popover has no Brick/Chart switch and always shows the resolved layout after startup, restart, and cross-window settings changes.
- Settings shows three real-data presets; browsing does not write, Apply persists exactly once, and the selected state matches resolved settings.
- Area, Heatmap, Quota Focus, empty-data, stale-data, and env-overridden states all render without fake values.
- Mouse movement works at the preview's upper-right corner; hover scale, tilt, glow, pointer leave, keyboard navigation, touch scrolling, and reduced-motion behavior work as described.
- Existing Timeline and Quota behavior remains unchanged.

## Verification

- UI/mock contract tests: `menubarView` resolve and patch merge.

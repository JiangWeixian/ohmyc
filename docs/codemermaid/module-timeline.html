concept

Read-only SQLite queries

The timeline module queries ~/.config/ohmyc/timeline.db (or $OHMYC_HOME/timeline.db) via rusqlite. It's read-only — it never writes to the database. The database is populated by Claude Code itself during sessions; OhMyC reads it to display analytics in the UI.

At ~900 lines, this is the second-largest file in the crate after profiles/activation.rs. The size comes from the variety of queries: heatmaps by date, project lists, session details, event timelines, year summaries, and status checks. Each query returns a typed struct via serde::Serialize.

concept

Query types and metrics

The Metric enum (Sessions, Turns, Tokens) drives the heatmap query. The UI passes a metric string like "sessions" and the heatmap query returns date-bucketed counts. The HeatmapPoint struct serializes as {"date": "2026-01-15", "value": 42}.

Other queries return SessionRow (session details with timestamps, model names, token counts), project lists, event timelines, and year summaries. All queries use parameterized SQL to prevent injection — the module constructs queries with ? placeholders and binds values.

concept

Test database infrastructure

The test_db submodule (only compiled under #[cfg(test)]) provides a test database builder that creates an in-memory SQLite database, seeds it with test data, and returns a connection. This allows unit tests to verify query logic without needing a real timeline.db file on disk.

takeaway

The timeline module is a read-only SQLite query layer. It provides typed results for heatmaps, sessions, projects, events, and analytics. The Metric enum drives the heatmap query. The test database submodule enables unit testing without a real database file. All SQL queries use parameterized inputs to prevent injection. The module uses the same env-override pattern as store for testability.

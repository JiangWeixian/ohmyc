concept

Read-only plugin access

The plugins module reads from ~/.claude/plugins/installed_plugins.json and known_marketplaces.json. It's read-only — plugin installation and removal happen through Claude Code itself. OhMyC reads the state to show the user what's installed and to merge enabled-state during profile activation.

The module mirrors the TypeScript PluginService in the Claude Code CLI. The data structures (PluginInstall, PluginManifest) are designed to round-trip with the TypeScript types, preserving unknown fields via #[serde(flatten)].

code-walk

PluginInstall with passthrough fields

crates/ohmyc-core/src/plugins.rs 
1#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]2#[serde(rename_all = "camelCase")]3pub struct PluginInstall {4    pub version: String,5    pub installed_at: String,6    pub last_updated: String,7    #[serde(flatten)]8    pub extra: Map<String, Value>,9}
L7–8

#[serde(flatten)] captures any unknown fields into extra. This is the passthrough pattern — Claude Code may add fields the Rust code doesn't know about, and this ensures JSON round-trips don't lose data.

concept

Enabled-state merge from settings

The list_plugins function reads installed_plugins.json and then reads settings.json to find the enabledPlugins map. Each plugin's enabled state comes from settings, not from the install record. This separation means the user can disable a plugin without uninstalling it.

During profile activation, the activation engine writes a new installed_plugins.json that includes the profile's plugin list, and merges enabled-state into settings. The undo stack records both files for rollback.

takeaway

The plugins module is a read-only bridge to Claude Code's plugin data. The #[serde(flatten)] passthrough pattern ensures forward compatibility when Claude Code adds new fields. Enabled-state lives in settings.json, separate from install records, allowing disable-without-uninstall. During profile activation, the activation engine writes both plugin files and records them on the undo stack.

concept

Three config sources, one module

The configs module reads three types of configuration from ~/.claude: MCP servers from .mcp.json, hooks from settings.json, and LSP servers from settings.json. Each type has its own entry struct (McpEntry, HookEntry, LspEntry) that tags the data with source and scope metadata.

All three are read-only. The module reads from claude_home and the settings module — it doesn't write anything. This is a pure extraction layer that turns raw JSON into typed entries for the UI.

L2

Reads ~/.claude/.mcp.json — a dot-prefixed file in the claude home directory. This is Claude Code's MCP server configuration format.

L4, L7

Two defensive returns: file missing → empty list, mcpServers field missing or not an object → empty list. Missing or malformed config is never an error.

L12–13

Every entry is tagged source: "local" and scope: "global". Future slices will add profile-scoped and project-scoped entries with different tags.

concept

Hooks flattening

Hooks in settings.json have a nested shape: { event: [{ matcher?, hooks: [...] }] }. The configs module flattens this into linear HookEntry structs: one entry per hook, with the event name and matcher data attached. Each entry is tagged with source and scope like MCP entries.

This flattening makes hooks easier for the UI to render — a flat list instead of nested arrays. The original nesting is a Claude Code internal format that doesn't need to leak into the UI layer.

quiz

Check your understanding

Why does mcp_servers() return an empty list when .mcp.json is missing instead of an error?
AThe file is expected to be missing in most installations
BMCP servers are optional — Claude Code works fine without any configured, so missing config is valid state
CThe module doesn't have access to the error type
DIt's a performance optimization to avoid file system calls
Correct: B — MCP servers are an optional feature. Many Claude Code installations have no MCP servers configured. The module returns an empty list so the UI can show "no MCP servers configured" without special error handling. A is close but not precise — it's about optionality, not expectation. C is wrong (the module imports ApiError). D is wrong (the file system call still happens).
takeaway

The configs module is a read-only extraction layer. It reads MCP servers from .mcp.json and hooks + LSP servers from settings.json, returning typed entries tagged with source and scope metadata. The hooks flattening transforms Claude Code's nested format into a flat list. Missing or malformed config files always return empty results, never errors.

concept

Two directories, two responsibilities

The store module mirrors claude_home but for OhMyC's own data. store::base_dir() resolves $OHMYC_HOME (default ~/.config/ohmyc/). Under that root, the store manages agents, skills, commands, model configs, and profiles. The submodules — provenance, references, model_configs — each own a specific concern.

The key insight: ~/.claude is Claude Code's live config (read by Claude Code at runtime). $OHMYC_HOME is OhMyC's staging area (managed by OhMyC). The store module never writes to ~/.claude — that only happens during profile activation in the profiles module.

L6–9

Path traversal defense: reject empty names, .., forward slashes, and backslashes. Without this, a name like ../../../etc/passwd would let PathBuf::join escape the store directory. This is a standard security guard for filesystem-based CRUD.

L17

ModelConfigs returns false here because model configs use their own existence check with different name rules (allowing slashes for provider-prefixed names like anthropic/sonnet-4).

concept

Provenance: where did this come from?

The provenance submodule reads <store>/.metadata/imports.json — an index that records where each component was imported from (importPath) and when (importedAt). When present, this metadata enriches the component's response to the frontend, showing "Imported from GitHub on 2026-03-15" in the UI.

The read is defensive: missing file returns an empty map, malformed JSON returns an empty map. The provenance index is optional — the system works fine without it, just without import metadata.

concept

Reference checking: the safe-delete gate

The references submodule is the safe-delete gate covered in the Build-Up Walkthrough. Before deleting a component, referencing_profiles() scans every profile's JSON for references to the target. If any profile depends on it, the delete returns ApiError::ReferencedBy with the list of dependent profiles.

The implementation is straightforward directory scanning: iterate <profiles_dir>/*//profile.json, parse each JSON, check if the component name appears in the relevant array (agents, skills, commands) or string field (modelConfig). Skip dot-prefixed dirs, skip malformed JSON, skip missing files. The result is sorted alphabetically.

concept

Model configs with slash-separated names

Model configs (model_configs.rs) are the exception to the "no slashes in names" rule. Names like anthropic/sonnet-4 are allowed because they map to subdirectories: store/model-configs/anthropic/sonnet-4.json. The safety check is different — instead of rejecting all slashes, it rejects .. path segments, leading/trailing slashes, and double slashes.

Each model config is a JSON file with name, apiKey, baseUrl, modelName, and provider fields. During profile activation, the activation engine reads these fields to inject environment variables into Claude Code's settings.

takeaway

The store module is OhMyC's staging area. It mirrors ~/.claude but is owned by OhMyC. The ComponentKind enum is the shared discriminant across listings, provenance, and references. The path-traversal guards prevent user-supplied names from escaping the store directory. The provenance index enriches component data with import metadata. The reference checker gates deletions to prevent breaking active profiles.

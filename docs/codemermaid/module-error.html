concept

The ApiError enum

Every module in ohmyc-core returns Result<T, ApiError>. It's a single, flat enum — not a trait object, not a wrapped anyhow. The reason: the frontend needs a stable JSON shape with a code tag (like "NotFound" or "ActivationBlocked") and a detail payload. That's what #[serde(tag = "code", content = "detail")] gives us — each variant serializes as {"code": "VariantName", "detail": ...}.

The thiserror derive gives Display and Error impls for free, while serde handles the JSON wire format. Notice the tradeoff: this is not a general-purpose error type. It's an API contract between the Rust backend and the TypeScript frontend.

L1–2

Three derives: Debug for logging, Error (thiserror) for Display + Error trait, Serialize (serde) for JSON. The #[serde(tag, content)] attribute is the wire-format contract — every error becomes {"code": "...", "detail": ...}.

L16–20

ReferencedBy carries structured data — the list of profiles that reference the component. The #[serde(rename)] attribute ensures the JSON key is "referencedBy" (camelCase), matching the TypeScript frontend's expected shape.

L23–26

ActivationBlocked includes the list of missing components. The UI reads detail.missing to render the "these components are missing" dialog before activation.

concept

Structured error variants

Notice the pattern — the simple variants (InvalidInput, Io, Conflict) carry a single string, while the complex variants (ReferencedBy, ActivationBlocked) carry structured data. The simple ones are for logging and display; the complex ones are for UI interaction.

ReferencedBy exists specifically for the safe-delete flow: when you try to delete a component, and the reference checker finds profiles that depend on it, the error includes those profile names so the UI can ask "are you sure?" instead of just saying "conflict." ActivationBlocked does the same for profile activation — it lists the missing components so the user knows what to install first.

The From<std::io::Error> impl converts any IO error into ApiError::Io(message), keeping the ergonomics clean — modules can use ? on IO results directly.

takeaway

ApiError is the crate's shared error vocabulary. It's not a general-purpose error type — it's a frontend API contract. The serde-tagged format gives a stable JSON wire shape. Simple variants carry strings; complex variants (ReferencedBy, ActivationBlocked) carry structured data that drives UI interaction. Once you understand this enum, every Result<T, ApiError> in the crate reads clearly.

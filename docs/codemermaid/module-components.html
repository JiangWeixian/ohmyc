concept

Three readers, one pattern

The components module contains three sub-readers — agents, skills, commands — that all follow the same pattern: scan a directory for .md files, parse YAML frontmatter, filter out entries missing required fields (name + description), and return typed structs. The shared types (ComponentSource, Origin, Scope) and the read_md_or_skip helper live in mod.rs, while each reader implements its own list, get, create, update, and delete functions.

Skills are slightly different: they're directories (not single files) — a skill is identified by a directory containing a SKILL.md file. This is why component_exists in the store checks for directory existence for skills but file existence for agents and commands.

The Agent struct and list function

crates/ohmyc-core/src/components/agents.rs 
1pub fn list(dir: &Path) -> Result<Vec<Agent>, ApiError> {2    if !dir.exists() {3        return Ok(Vec::new());4    }5    let mut out: Vec<Agent> = Vec::new();6    for entry in std::fs::read_dir(dir).map_err(ApiError::from)? {7        let entry = entry.map_err(ApiError::from)?;8        let path = entry.path();9        if path.extension().and_then(|s| s.to_str()) != Some("md") {10            continue;11        }12        let raw = match read_md_or_skip(&path)? {13            Some(s) => s,14            None => continue,15        };16        if let Some(agent) = parse_agent(&filename, &raw)? {17            out.push(agent);18        }19    }20    out.sort_by(|a, b| a.id.cmp(&b.id));21    Ok(out)22}
L2–3

Missing directory is not an error — return empty list. This is the same defensive pattern used across every reader module.

L9

Only process .md files. Non-markdown files in the agents directory (README, .gitkeep, etc.) are silently skipped.

L16

parse_agent returns None for files missing required name or description fields. Invalid entries are filtered, not errored — a README file in the agents dir should not crash the listing.

L20

Alphabetical sort by ID for stable ordering. The UI shows agents in a consistent order regardless of filesystem traversal order.

code-walk

read_md_or_skip: the vanishing-file policy

crates/ohmyc-core/src/components/mod.rs 
1pub fn read_md_or_skip(path: &std::path::Path) -> Result<Option<String>, ApiError> {2    match std::fs::read_to_string(path) {3        Ok(s) => Ok(Some(s)),4        Err(e) if e.kind() == std::io::ErrorKind::NotFound => Ok(None),5        Err(e) => Err(ApiError::Io(format!("read {}: {e}", path.display()))),6    }7}
L4

NotFound is Ok(None) — the file vanished between read_dir and read_to_string. This is a race condition that happens when the user deletes a file while OhMyC is listing the directory. It's benign — skip the file.

L5

All other IO errors (permission denied, disk full, transient FS errors) surface as ApiError::Io. The policy: missing is fine, broken is not.

concept

Frontmatter boundary validation

The frontmatter submodule uses the gray_matter crate to parse YAML between --- delimiters. The boundary validation is strict: null or non-object frontmatter is rejected immediately. This prevents silent data loss — if the YAML is malformed, the caller gets an error instead of an empty frontmatter object where every field lookup returns None.

The stringify function writes frontmatter back to YAML, preserving arbitrary fields. Round-trip correctness is tested — any frontmatter that parses should stringify back to the same data.

concept

Safe names and CRUD

Every component reader uses is_safe_name() to validate user-supplied names before using them in file paths. The rules: only ASCII alphanumeric, underscore, and dash. No dots (prevents .env), no slashes (prevents path traversal), no spaces. This guard runs before any filesystem operation in get, create, update, and delete.

The CRUD operations follow standard patterns: create writes a new file (errors on conflict), update merges frontmatter and replaces content, delete removes the file. All operations use the frontmatter module's stringify function for consistent formatting.

Check your understanding

Why does list silently skip files missing name and description instead of returning an error?
AThe agents directory may contain non-agent files (README, templates) that are valid markdown but not agents
BErrors would be too expensive to handle in the calling code
CThe frontmatter parser doesn't distinguish between missing and malformed YAML
DIt's a performance optimization to avoid parsing invalid files
Correct: A — The agents directory is user-managed; it may contain any markdown files. A README or template file is valid content but not a valid agent. Filtering (not erroring) keeps the listing resilient. B is wrong (error handling is cheap). C is wrong (the parser does distinguish — malformed YAML returns ApiError::Parse). D is wrong (the file is parsed regardless).
takeaway

The components module reads .md files from ~/.claude/{agents,skills,commands}/ into typed Rust structs. Every reader follows the same pattern: scan, filter by extension, parse frontmatter, skip invalid entries, sort by ID. The read_md_or_skip helper centralizes the "file vanished" policy. The is_safe_name guard prevents path traversal. The frontmatter boundary validation catches malformed YAML at the parse boundary.
